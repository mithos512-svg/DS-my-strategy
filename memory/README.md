## Что это за проект

Личная система самоорганизации в GitHub-репозитории DS-my-strategy, управляемая через
диалог с Claude (IWE). Пользователь проходит курсы S1 (системная инженерия) и S2
(стратегирование) на aisystant, ведёт учёт питания, веса, времени и практикует
стратегирование по методу PD.METHOD.008 (пакет PACK-personal).

## Структура репозитория

**current/** - активные, часто обновляемые документы:

- `DayPlan YYYY-MM-DD.md` - план/итоги текущего дня (создаётся на Day Open, закрывается на Day Close)
- `WeekPlan YYYY-MM-DD.md` - план недели (дата = понедельник недели), создаётся на Strategy Session
- `Strategy-YYYY-MM.md` - документ стратегии месяца (PD.WP.006): состояние, калибр, ТОС, R1-RN
- `PriorityProjects-YYYY-MM.md` - список приоритетных проектов месяца (PD.WP.007), ранжирован по критериям табл. 8.4
- `lifework-tracker.md` - трекер рекомендаций Стратега по lifework-пакету (PD.FORM.090, уровни 1-6)
- `MonthlySession-YYYY-MM-record.md` / `MonthlySession-*-prep.md` - протокол/подготовка месячной Strategy Session
- `DefensePrep-S1S2.md` - подготовка к финальной защите резидентур S1+S2 (дедлайн 23.08.2026), задание 10.2 S2
- `nutrition-log/YYYY-MM-DD.md` - учёт питания по приёмам пищи за день (ккал, белок, клетчатка на каждый приём и накопительный итог); см. раздел "Шаблоны приёмов пищи" выше про сокращения
- `learning-journal/YYYY-MM-DD.md` - заметки по S1/S2 со сверкой через первоисточники
- `weight-log.md` - дневник веса (рост 182см), включает периодические замеры талии/шеи (% жира US Navy)
- `health-log/raw/YYYY-MM-DD.md` - сырые данные сна из Apple Health (секунды Core/Deep/REM), автоматически заливаются через Shortcuts на телефоне
- `health-log/YYYY-MM-DD.md` - обработанный дневник сна (минуты + sleep score 0-100), генерируется автоматически GitHub Action (`.github/workflows/health-log.yml`, скрипт `scripts/process_health_log.py`) при коммите в raw/
- `Dissatisfactions.md` - список неудовлетворённостей (триады: проблема+состояние+эмоция), PD.WP.005
- `hypotheses-log.md` - журнал гипотез (утверждение/уверенность/критерий фальсификации/дата сверки)
- `time-investment-log.md` - учёт времени по активностям (связано с критерием таблицы 8.4)
- `S2-concepts-8-9-review.md` - проработка таблицы понятий 8.9 (S2) в диалоге, по одному понятию
- `projects/<name>/` - материалы отдельных проектов (approach.md, capability-modeling-log.md, namecard-program.md и т.п.)
- `posts/` - черновики постов для публикации

**memory/** - конфигурация и правила:

- `day-rhythm-config.md` - ГЛАВНЫЙ файл правил. Все обязательные шаги Day Open/Day
Close/недельной сессии. Читать целиком в начале нового чата.
- `inbox/fleeting-notes.md` - мимолётные заметки, не разобранные по категориям (см.
Фазу 1b недельной сессии в day-rhythm-config.md)
- `fpf-seminars/` - конспекты семинаров FPF
- `commands/` - самодостаточные команды по ключевому слову, вызываемые из любого
чата без поднятия остального контекста (например `commands/weight-chart.md`)

**archive/day-plans/** - закрытые DayPlan прошлых дней. **archive/** (корень) - закрытые WeekPlan прошлых недель.

## Внешние skill'ы (не в этом репозитории)

Базовые алгоритмы `day-open`, `week-close` и т.п. подгружаются извне (шаблонный
репозиторий FMT-exocortex-template) через `personal_load_skill`/`knowledge_load_skill`,
а не хранятся здесь. `extensions/day-open.before.md` - это только локальное
расширение поверх внешнего skill (велит сначала прочитать README+config), а не сам
алгоритм. Если загрузка skill вернёт ошибку платформы - см. правило про сбои
skill/backend в day-rhythm-config.md: Claude обязан явно сказать об этом, а не тихо
выполнить урезанный алгоритм.

Для платформенного (L2) знания (PACK-personal и т.п.) используй `knowledge_search` /
`knowledge_get_document` - этот путь работал стабильно, когда `personal_load_skill`
был недоступен.

**Важно (найдено 17.08.2026):** skill `day-open`, загружаемый через
`knowledge_load_skill`, рассчитан на среду Claude Code с локальным диском
(`git log`, `gh issue list`, VS Code dashboard, Scout, бот QA, scheduler-отчёты
по путям вроде `/Users/tserentserenov/IWE/...`). В веб/мобильном чате Claude.ai
этих возможностей нет - там доступны только IWE-инструменты (personal_search/
personal_write/knowledge_*) и, при разрешении, календарь. В этой среде полный
алгоритм skill выполнить нельзя буквально - нужно явно говорить пользователю,
какие шаги пропущены, и подтягивать что можно вручную через personal_search/
personal_get_document, а не молчать об ограничении.

**Также важно (17.08.2026):** индекс поиска (`personal_search`/`personal_get_document`)
периодически отстаёт от реального содержимого GitHub (стухшие результаты сразу
после записи, особенно для только что применённых через `personal_write`
изменений). Если нужна гарантированно полная и точная выдержка из файла (перед
перезаписью существующего документа, при поиске точного термина по всему
репозиторию) - надёжнее склонировать репозиторий через `bash_tool`
(`git clone https://github.com/mithos512-svg/DS-my-strategy.git`) и использовать
`grep`/`cat` напрямую, а не полагаться на `personal_get_document`/`personal_search`.
Особенно важно при редактировании файла через `personal_write`: сначала получить
гарантированно свежий полный текст (git clone), иначе есть риск перезаписать
поверх устаревшей версии и потерять данные (как уже случилось с этим файлом).

## Постоянные правила (кратко, полностью - в day-rhythm-config.md)

1. Обратная связь по S1/S2/FPF - всегда со сверкой через первоисточник (IWE knowledge search), явно указывать откуда, и явно говорить если источник не нашёлся.
2. Day Close по субботам - напомнить про замер талии/шеи на воскресенье.
3. Day Close каждый день - спросить про неудовлетворённости дня.
4. Day Close каждый день - показать весь time-investment-log.md за день, спросить всё ли записано.
5. Недельная сессия - 7 фаз (0-6), приведено к PD.METHOD.008, калибр/lifework-пакет сознательно отложены как преждевременные (до 2027-02, см. lifework-tracker.md). Отдельно (не Day Close): R1 месяца (кирпичи ступени 1) не трекается отдельной строкой в плане - идёт через обычный ритм Day Open/Close, проверяется по факту на месячной сессии.
6. Уточняющие вопросы пользователю - только текстом в чате (добавлено 17.08). НЕ использовать интерактивный
   инструмент-виджет с кнопками для уточняющих вопросов (в веб/мобильном интерфейсе Claude пользователь не видит
   весь вопрос целиком в таких окнах). Формулировать варианты как обычный текст сообщения.
7. Команды по ключевому слову (добавлено 17.08) - см. раздел "Команды по ключевым
   словам" выше и папку `memory/commands/`. Если пользователь произносит
   зарегистрированное там ключевое слово в любом чате - выполнять команду по
   инструкции из соответствующего файла, не спрашивая лишний раз.
8. Перед перезаписью существующего файла через `personal_write` (добавлено 17.08,
   после инцидента с этим README) - получать гарантированно свежий полный текст
   (через `git clone` + `cat`/`grep` в bash_tool, не через `personal_get_document`/
   `personal_search`, которые могут отставать), иначе есть риск затереть данные.
9. (см. полный список 9-26 в day-rhythm-config.md - РП каждой помидорки,
   чтение+комментирование постов сокурсников, месячная рефлексия и др.)
