# README - точка входа для нового чата с Claude

> Если это новый чат (текущий достиг лимита) - прочитай этот файл первым, затем
> memory/day-rhythm-config.md целиком, затем самые свежие файлы из current/ (см. ниже).
> После этого можно продолжать как обычно - Day Open/Close, S1/S2, питание и т.д.

## Что это за проект

Личная система самоорганизации в GitHub-репозитории DS-my-strategy, управляемая через
диалог с Claude (IWE). Пользователь проходит курсы S1 (системная инженерия) и S2
(стратегирование) на aisystant, ведёт учёт питания, веса, сна, времени и практикует
стратегирование по методу PD.METHOD.008 (пакет PACK-personal).

## Сокращения

- **неуд** = неудовлетворённость (см. Dissatisfactions.md, PD.WP.005)
- **НЭП** = та же неудовлетворённость, полная форма термина по PD.METHOD.008 (триада "проблема + неудовлетворённость + эмоция")
- **СВД** = стандартный вечерний десерт (см. memory/templates/evening-dessert.md)
- **ТОС** = Теория ограничений (Theory of Constraints)
- **РП** = рабочий продукт

## Структура репозитория

**current/** - активные, часто обновляемые документы:
- `DayPlan YYYY-MM-DD.md` - план/итоги текущего дня (создаётся на Day Open, закрывается на Day Close)
- `WeekPlan YYYY-MM-DD.md` - план недели (дата = понедельник недели), создаётся на Strategy Session
- `Strategy-YYYY-MM.md` - документ стратегии месяца (PD.WP.006): состояние, калибр, ТОС, R1-RN
- `PriorityProjects-YYYY-MM.md` - список приоритетных проектов месяца (PD.WP.007), ранжирован по критериям табл. 8.4
- `lifework-tracker.md` - трекер рекомендаций Стратега по lifework-пакету (PD.FORM.090, уровни 1-6)
- `MonthlySession-YYYY-MM-record.md` - протокол месячной сессии (что решили/отклонили/перенесли)
- `nutrition-log/YYYY-MM-DD.md` - учёт питания по приёмам пищи за день (ккал, белок, клетчатка на каждый приём и накопительный итог)
- `learning-journal/YYYY-MM-DD.md` - заметки по S1/S2 со сверкой через первоисточники
- `weight-log.md` - дневник веса (рост 182см), включает периодические замеры талии/шеи (% жира US Navy)
- `health-log/raw/YYYY-MM-DD.md` - сырые данные сна из Apple Health (секунды Core/Deep/REM),
  автоматически заливаются через Shortcuts на телефоне (настроено 28.07, автозапуск по таймеру подтверждён 30.07,
  но 31.07 и 01.08 не сработал - требует проверки)
- `health-log/YYYY-MM-DD.md` - обработанный дневник сна (минуты + sleep score 0-100),
  генерируется автоматически GitHub Action (`.github/workflows/health-log.yml`,
  скрипт `scripts/process_health_log.py`) при каждом коммите в health-log/raw/.
  Формула score (с 29.07) - на основе научных норм долей фаз сна (Deep 13-23%,
  REM 20-25%) + длительность сна к цели 7ч, не на произвольных весах.
- `posts/YYYY-MM-DD-*.md` - черновики постов/заметок для публикации - живут в current/, а не в корне репозитория; формат - см. раздел "Формат постов" ниже
- `Dissatisfactions.md` - список неудовлетворённостей (триады: проблема+состояние+эмоция), PD.WP.005
- `hypotheses-log.md` - журнал гипотез (утверждение/уверенность/критерий фальсификации/дата сверки)
- `time-investment-log.md` - учёт времени по активностям (связано с критерием таблицы 8.4)
- `S2-concepts-8-9-review.md` - проработка таблицы понятий 8.9 (S2) в диалоге, по одному понятию - ЗАВЕРШЕНО (14/14)

**archive/** - закрытые DayPlan/WeekPlan, закрытые месячные сессии и legacy-версии
документов. Правило: попадание файла сюда означает, что его больше НЕТ в current/
(архивация = перенос, не копирование - см. day-rhythm-config.md, правило от 02.08).
current/ и archive/ не должны иметь файлов с одинаковым именем одновременно.

**scripts/** - вспомогательные скрипты для автоматизации (сейчас: обработка health-log).

**memory/** - конфигурация и правила:
- `day-rhythm-config.md` - ГЛАВНЫЙ файл правил. Все обязательные шаги Day Open/Day
  Close/недельной сессии. Читать целиком в начале нового чата.
- `inbox/fleeting-notes.md` - мимолётные заметки, не разобранные по категориям (см.
  Фазу 1b недельной сессии в day-rhythm-config.md)
- `iwe-roadmap.md` - чеклист 14 элементов культуры работы в IWE, разбирается на Strategy Session
- `templates/` - шаблоны еды, каждый - отдельный файл, вызывается голосовой командой:
  - `breakfast-standard.md` ("завтрак стандартный") - банан+творог+кофе, ~334 ккал
  - `breakfast-oatmeal.md` ("каша стандартная") - овсянка+голубика+груша+кофе, ~305 ккал
  - `snack-standard.md` ("полдник стандартный", вариант B) - protein pudding+черника+морковь+груша+protein bar, ~488 ккал
  - `evening-dessert.md` ("вечерний десерт стандартный" / СВД) - тёмный шоколад+орехи+чернослив, ~286 ккал
  - `protein-bar-standard.md` ("стандартный батончик") - SportyFeel Crunchy Protein Bar, ~195 ккал/16г белка/4г клетчатки

## Формат постов (current/posts/)

Как писать пост по заметкам недели ("напиши черновик поста по S1/S2/... в формате posts").
Эталоны: `2026-08-03-s2-insights-w31.md`, `2026-08-02-s1-week-notes.md`.

**Файл:** `current/posts/YYYY-MM-DD-<тема>-w<номер недели>.md` (дата = день создания).

**Frontmatter:**
```
---
type: post
published: false
platform: МИМ клуб (systemsworld.club)
created: YYYY-MM-DD
published_at:
status: черновик
---
```
После публикации: `published: true`, `published_at`, `status: опубликован`.

**Структура тела:**
1. `# Заголовок` - конкретный, с интригой/числом, без слова "пост" и без внутренних кодов.
2. Дисклеймер цитатой: `> *Пост подготовлен при участии IWE / Claude на основе <источники: файлы репозитория, learning-journal W##>*`.
3. Интро 2-4 предложения: что делал, каким методом, что получилось - и почему делюсь.
4. 4-6 пронумерованных инсайтов: `**N. Тезис одной строкой**` + абзац 3-6 предложений.
5. Разделитель `---`.
6. `**Открытый вопрос клубу:**` + 1-2 вопроса, приглашающих к обсуждению опыта читателя.

**Принципы содержания:**
- Не конспект курса, а личные инсайты: где источник поправил меня, что резонировало, что применил на практике. Лучший материал - расхождения "моя версия vs источник".
- Каждый тезис со ссылкой на источник в скобках (номер раздела курса: 8.12, 9.3-9.4, PD.METHOD.008 и т.п.) - сверка должна быть уже сделана в заметках, не выдумывать.
- Первое лицо, разговорный, но плотный тон. Без воды и мотивационных клише.
- Публичные названия, не внутренние коды: "резидентура «Практики саморазвития»" (не "S2"), "«Системное саморазвитие»" (не "S1"). Внутренние имена файлов можно в скобках в дисклеймере.
- Не повторять темы предыдущих постов той же серии (проверить прошлые *-insights-*).
- Хорошее завершение - мостик от теории к живой практике (что реально сделал/изменил).

## Внешние skill'ы (не в этом репозитории)

Базовые алгоритмы `day-open`, `week-close` и т.п. подгружаются извне (шаблонный
репозиторий FMT-exocortex-template) через `personal_load_skill`/`knowledge_load_skill`,
а не хранятся здесь. `extensions/day-open.before.md` - это только локальное
расширение поверх внешнего skill (велит сначала прочитать README+config), а не сам
алгоритм. Если загрузка skill вернёт ошибку платформы - см. правило 15 ниже:
Claude обязан явно сказать об этом, а не тихо выполнить урезанный алгоритм.

Для платформенного (L2) знания (PACK-personal и т.п.) используй `knowledge_search` /
`knowledge_get_document` - этот путь работал стабильно 02.08, когда `personal_load_skill`
был недоступен (см. правило 15).

## Постоянные правила (кратко, полностью - в day-rhythm-config.md)

1. Обратная связь по S1/S2/FPF - всегда со сверкой через первоисточник (IWE knowledge search), явно указывать откуда, и явно говорить если источник не нашёлся.
2. Day Close по субботам - напомнить про замер талии/шеи на воскресенье.
3. Day Close каждый день - спросить про неуды дня.
4. Day Close каждый день - показать весь time-investment-log.md за день, спросить всё ли записано.
5. Day Close каждый день - обновить раздел "Текущий статус" в этом README.
6. Day Close каждый день, последним шагом - самостоятельно запустить knowledge_reindex_source(source="DS-my-strategy") (не напоминание пользователю, а действие Claude).
7. Day Close каждый день - показать сон (Core/Deep/REM, длительность) и sleep score из health-log за сегодня.
8. Перед созданием нового файла/пути - сначала проверить существующую структуру (personal_search / это README), не изобретать новые папки в корне без необходимости; по умолчанию новые типы документов - в `current/<тип>/`.
9. При упоминании сокращения/термина, которого нет в этом README (например "СВД") -
   сначала искать по всему репозиторию (personal_search/templates), и только если
   нигде не найдено - спрашивать пользователя, что это значит.
10. Данные из personal_get_document иногда отстают от реального состояния репозитория
    (индекс поиска обновляется с задержкой) - если результат выглядит неожиданно
    "старым" сразу после записи, перепроверять через прямой запрос к
    raw.githubusercontent.com перед тем, как делать выводы.
11. На фото еды - всё, что попало в кадр, должно быть посчитано и записано в
    nutrition-log (пользователь не фотографирует одну и ту же еду повторно). Если
    непонятно, что именно на фото или сколько порций - уточнять у пользователя, а
    не додумывать самому, но не пропускать объект молча.
12. В каждом приёме пищи и в накопительном итоге дня всегда показывать не только
    ккал и белок, но и клетчатку.
13. На Week Close - архивация DayPlan/WeekPlan это ПЕРЕНОС (запись в archive/ +
    немедленное удаление из current/ одним связным действием), а не копирование.
    Нельзя оставлять между этими шагами паузу - если прервётся, при следующем
    открытии чата первым делом доделать удаление.
14. На месячной Strategy Session - проверять current/ на дрейф от archive/
    (закрытые DayPlan/WeekPlan старше текущей недели, дубли по имени файла,
    устаревшие legacy-версии) и доархивировать найденное по правилу 13.
15. Если вызов любого инструмента IWE (personal_load_skill, personal_reindex_source,
    personal_delete и т.п.) вернул ошибку платформы - явно сказать об этом
    пользователю, не продолжать молча урезанным алгоритмом, и по возможности
    вручную восстановить пропущенный шаг из доступных данных репозитория.
16. Стоп-лист хвостов (счётчик переносов, R2 месяца, добавлено 03.08) - задача,
    перенесённая 3 раза подряд, требует на Day Close явного решения: закрыть
    минимальной версией / отбросить с записанной причиной / переназначить на
    конкретную дату. Полностью - см. day-rhythm-config.md.
17. "Закрывай помидорки" / "время: ..." (добавлено 03.08) - это ТОЛЬКО запись в
    time-investment-log (+ можно отметить статус РП в DayPlan), не полный Day Close.
    Не путать с "закрываем день"/"Day Close" - тем самым полным ритуалом (правила 3-7).

Отдельно (не Day Close): недельная сессия - 7 фаз (0-6), приведено к PD.METHOD.008,
калибр/lifework-пакет сознательно отложены как преждевременные до первой месячной
сессии (проведена 02.08 - теперь калибр/lifework входят и в недельную практику, Фаза 2b).
