# Learning Journal - 4 ноября 2026

## R3.4:Tasks1 - Вспоминаем разные типы описаний

Источник: MimEcoSys/docs, `professional/modeling-2/04-practice-of-creating-models/03-recalling-different-types-of-descriptions.md`; опора - R3.4:2 «Уровни абстракции» (`02-levels-of-abstraction-in-modeling.md`). Синхронизация репозитория 24.10.2026.

Все три случая взяты на одной лестнице DQ, чтобы было видно, как каждый шаг абстрагирования отбрасывает признак.

### 1. Нечто конкретное, индивиды

Разбор инцидента качества: «запись продукта ID 100234 в справочнике продуктов SAP на 23.10» - пустое поле GTIN, из-за чего «дашборд Sales Overview (ID D-17)» за 23.10 показал неполные продажи. Адресат - дата-инженер и владелец данных: нужно исправить одну запись и понять одну причину.

### 2. Нечто в узких классах

DQ-правило для системы DG/DQ: «у каждой записи справочника продуктов SAP поле GTIN заполнено и имеет 13 цифр». Правило описывает не одну запись, а весь класс «записи справочника продуктов SAP» и применяется к каждой автоматически. Адресат - Data Steward домена «продукт»: метод проверки, который работает сам на сотнях тысяч записей.

### 3. Нечто в широких, абстрактных классах

Roadmap системы доверия к данным для C-level: «покрытие критических доменов данных DQ-мониторингом - больше 90%», «Data Trust Score - единая метрика доверия к данным». Здесь нет ни записей, ни справочников, ни правил - только классы «критические домены данных», «DQ-мониторинг», «данные, которым доверяет бизнес». Адресат - топ-менеджмент: он принимает решения о широких классах ситуаций (бюджет, приоритеты, этапы), и конкретные записи ему не важны. Урок прямо называет таких адресатов: топ-менеджер, директор по развитию, инвестор.

### Лестница абстрагирования

«запись продукта ID 100234» (индивид) → «записи справочника продуктов SAP» (отброшен ID) → «мастер-данные о продуктах» (отброшена система-источник) → «критические домены данных» (отброшен вид домена) → «данные предприятия» (отброшена критичность).

### Где абстракция переходит в размытость (R3.4:2)

- «Критические домены данных» - абстракция с понятной референцией, но только пока перечень доменов записан. В roadmap он есть: продукт, поставщик, рецептура, ТОП-10. Без перечня это уже размытое понятие.
- «Данные, которым доверяет бизнес» - размытое понятие, как «справедливость» в уроке: каждый представляет доверие по-своему. Поэтому roadmap и вводит Data Trust Score - попытку заземлить размытое понятие через измеримую характеристику. Это тот случай-исключение из урока, когда размытость в описании допустима, потому что цель описания - её снизить.
