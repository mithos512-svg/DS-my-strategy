# Классификаторы для чек-листа: что о каждом объекте нужно уметь сказать заранее

> *Черновик подготовлен при участии IWE / Claude по заданию R3.4:Mod4 резидентуры «Рабочее моделирование в инженерии и менеджменте», со сверкой через FPF Library (C.16.P).*

Третий шаг сквозного задания R3.4. Описание - чек-лист-шаблон «Как выглядит „хорошо“ для контроля устранения проблем качества данных». В прошлых постах были глоссарий и уровни детализации; теперь - классификаторы.

Мысль урока R3.4:8, которая для меня оказалась главной: раз я делаю **шаблон**, классификаторы составляю я как автор шаблона, а заполнять по ним будет команда внедрения. Значит, ещё до заполнения нужно решить, что именно можно будет сказать о каждом объекте - к каким классам его можно отнести. Каждый справочник получает имя - имя класса классов.

Верхняя онтология - 4D-экстенсионализм (BORO), как в курсе. Объекты и части - из разбиения R3.4:Mod3.

## Что заметил по ходу

**Классификаторы не нужно изобретать.** Роли и измерения качества уже описаны в DAMA-DMBOK, характеристики качества данных - в ISO/IEC 25012. Домены данных и классы систем-источников почти наверняка уже ведутся в практике управления мастер-данными. Урок прямо говорит, что MDM - это и есть поддержка мета-модели компании. Для меня это неожиданно связало учебное задание с тем, чем наша команда занимается каждый день.

**Измерение качества - не класс.** Сначала хотелось сделать справочник «измерения качества». Сверка по FPF подсказала: полнота или своевременность - это характеристики, а классифицируем мы проблемы. Поэтому справочник называется «проблемы по измерению качества», а классы - «проблема полноты», «проблема своевременности».

**Критичность без критерия не работает.** Критичность - характеристика с порядковой шкалой. Её значения можно использовать как классы, но только если в шаблоне есть правило отнесения: например, «критичная - блокирует отчётность или регуляторную выгрузку». Без такого правила каждый будет ставить критичность по ощущению - и справочник перестанет классифицировать.

**Не всё требует справочника.** Порог и срок устранения - это условие и обязательство, их значения задаются в атрибутах. Ими займусь в следующем задании.
